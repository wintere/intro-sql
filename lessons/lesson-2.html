Exploring the Database in Beekeeper Studio

The Beekeeper Studio Interface

On the left side of Beekeeper Studio, there is a navigation pane with three icons.

  • The first, a database symbol, allows you to inspect the structure and properties of the current database.
  • The second allows you to see your saved queries. We’ll talk about saving queries shortly.
  • Finally, the third allows you to see all the queries you’ve run in the current workspace, including ones you may not have saved.

SELECT, FROM, and LIMIT

For our first query, let’s list the first and last names of each customer known to have purchased music from the store. To do this, we need the keywords SELECT and FROM.

Click the + button in the Beekeeper Studio editor pane to open a new query console and type the following.

Unpacking a First SQL Query

SELECT FirstName, LastName 
FROM Customer;
  • FROM is the most important part of the query. It must be followed by the name of a table in the database.
  • SELECT is followed by comma-separated names of fields within that table.
  • Every SQL query ends with a semicolon ;.
Note

SQL is case-insensitive, but it’s best practice to capitalize keywords like SELECT and FROM. It makes it easier to distinguish between keywords and values, which are typically camel case or title case.

To change the order of columns in our ourput, we can rewrite the order as follows:

SELECT LastName, FirstName
FROM Customer;

As a shortcut, we can select all of the columns in a table using *:

SELECT *
FROM Customer;

The * symbol tells SQL to display all of the fields in the table from left to right.

Controlling Output with LIMIT

The Customer table has 59 rows, which is more than we want to read at once. Luckily, SQL has keyword that limits the number of rows returned.

At the end of any SQL command, just before the semicolon, use the keyword LIMIT followed by a number of rows to indicate how many rows we want to return.

  • LIMIT must be followed by a positive integer.
SELECT LastName, FirstName
FROM Customer
LIMIT 5;
LastName FirstName
Gonçalves Luís
Köhler Leonie
Tremblay François
Hansen Bjørn
Wichterlová František

Debugging SQL: Syntax and Spelling

You might have noticed that I’ve been entering each clause in these SQL queries in a specific order. SELECT comes before FROM which comes before LIMIT. This is because the grammar of SQL requires keywords to have a hierarchy and order. We will discuss the syntactic placement of each keyword as new ones are introduced.

As an example, let’s see what happens if we invert the order of SELECT and FROM in a query.

FROM Customer
SELECT Email
LIMIT 5;
near "FROM": syntax error

If you get a syntax error message when running a query, inspect the grammar of your query carefully.

The SELECT keyword must be followed by a * or the name or one or more columns in the table in the FROM clause. If you ask SQL to select a column that doesn’t exist, the query will fail.

SELECT email_address
FROM CUSTOMER
LIMIT 5;
no such column: email_address - Check that you only use double 
quotes (") for identifiers, not strings

When you see a no such column error message, check the spelling the name of each field in the SELECT clause. Remember you can use the Entity pane on the left side of Beekeeper Studio or the name and data type of each column in your database at any time; make sure the name matches exactly.

Sorting with ORDER BY

We may want to sort the results of a query by a particular column. We can do this in SQL by adding an ORDER BY clause to our query.

ORDER BY must followed by the name of one or more columns, and the ORDER BY clause always comes just before LIMIT.

SELECT *
FROM Artist
ORDER BY Name
LIMIT 3;
ArtistId Name
43 A Cor Do Som
1 AC/DC
230 Aaron Copland & London Symphony Orchestra

By default, ORDER BY sorts a field in ascending order: numeric fields start with the smallest number, and text fields like varchar start with the string that comes first in the alphabet.

Now, let’s try sorting a numeric field: the UnitPrice of a digital song in dollars and cents.

SELECT Name, UnitPrice
FROM Track
ORDER BY UnitPrice
LIMIT 3;
Name UnitPrice
For Those About To Rock (We Salute You) 0.99
Balls to the Wall 0.99
Fast As a Shark 0.99

Let’s say we want to see the most expensive songs first. That means we need to sort by UnitPrice in descending order. We can indicate this to SQL by adding DESC just after the field we want to sort by.

SELECT Name, UnitPrice
FROM Track
ORDER BY UnitPrice DESC
LIMIT 3;
Name UnitPrice
Battlestar Galactica: The Story So Far 1.99
Occupation / Precipice 1.99
Exodus, Pt. 1 1.99

Quiz: The Biggest Purchase

Write a query against the Invoice table to find the CustomerId, InvoiceDate, and Total of the single biggest purchase in the database. Hint: You will need to sort by Total.

TipAnswer 
SELECT CustomerId, InvoiceDate, Total
FROM Invoice
ORDER BY Total DESC
LIMIT 1;
CustomerId InvoiceDate Total
6 2025-11-13 00:00:00 25.86

We can even sort by multiple attributes, with a different attribute used to break ties. The following queries sorts by UnitPrice in ascending order, then breaks ties by sorting by track length in milliseconds.

SELECT UnitPrice, Milliseconds
FROM Track
ORDER BY UnitPrice, Milliseconds DESC 
LIMIT 3;
UnitPrice Milliseconds
0.99 1612329
0.99 1196094
0.99 1116734
